# 16｜简历文案编译器、成稿审查与独立子代理协议

适用阶段1–5、7；必须与02事实台账、03定位、07审稿联合使用。Harvard MCS 要求具体、主动、清晰、事实基础与易扫读；MIT 主张按岗位筛选经历并交代个人行动及结果，同时其AI使用指南提醒PAR不应机械套到所有条目；Yale 强调个人贡献、实际影响与可迁移技能 [P17–P20]。因此目标是建立“读者看到这个人为什么值得进一步了解”的推断依据，而不是吹嘘、操纵或保证录取。

## 1. 文案写作方针（六段编译链）
1. **还原原料**：从口语/文件提取主体、时间、地点、角色、问题、行动、协作者、产物、认可、证据。把润色与事实分开；标记自述、原始证据、推断和待确认。不要把“老师”自动写成共同作者或导师。
2. **建立读者决策模型**：目标要求→3–5个可证明信号（例如研究设计、临床观察、执行、协作、专业表达）。筛选对照：信号—证据—本人贡献—目标相关性；如果缺证据就不能硬写该能力。
3. **提炼价值**：每条经历先判断读者为什么关心，区分任务、行动、交付、实际影响和长期意愿。数字只有能证明范围/难度/变化/选择性时才保留；无可信数字用可核查产物，未完成的研究如实写进行中真实工作，不补未来承诺。荣誉按官方名，理性前置。
4. **组织叙事**：一份简历有同一身份主线；避免每条重复“提升了综合能力”。段落顺序可采用问题→行动→结果、贡献→对象→成果、角色→责任→证据、结论先行等不同结构。章节衔接靠内容关联与排序，无须添加散文式过渡句。学术论文、证书、奖项用标准条目，不能强行PAR。自介只保留可在后文证明的特点及申请目标，未来方向表达具体想学习/承担的任务，避免重复。
5. **语域与表达**：目标读者需要的准确术语首次自然引入；其他技术字段/内部实现删除或移至作品说明。精准动词反映贡献强度（主导/协调/参与/协助/观察/形成）；没有依据不升级头衔。“学术严谨”“成熟商务”“工程技术”“温和人文”“年轻创意”可差异化，但都禁止套话与虚构。个人品质以行为示例表现，不列空洞形容词。
6. **重编译及审稿**：每段有主张、事实支持、相关性和适宜篇幅。先写结构/读者价值，再做句子改写，最后删重复。将事实核验、缺点和技术限制保留在内部；只在影响读者理解资历时准确写必要的阶段状态。不要把能核查/未核查等编辑痕迹写成正文；缺关键信息又无法证实时避免该主张。用户可选看两种不同强调角度，不强制所有段落有两个版本。

## 2. 场景化编译示例（全部虚构，不得复制为真实履历）
| 自然语言／原版问题 | 不合格写法 | 有竞争力的准确方式 |
|---|---|---|
| “AI帮我写代码，我设计了课程复习工具，已经上线，学生能用。” | 独立开发行业顶尖平台，使用React、缓存、路由…… | 围绕课程复习痛点，设计知识组织和交互练习流程，协调AI工具完成网页并上线，持续核查学习体验。（上线和责任均需证据） |
| “同老师做了甲乳讲座课件，我主要编辑图片文字。” | 主持疾病科普讲座，参与临床疾病防治…… | 与临床教师协作制作甲乳疾病科普课件，负责图文编辑与知识呈现，面向公众组织诊疗相关基础信息。（不声称讲者） |
| “我做了调查，只有21份问卷。” | 收集21份有效样本，成果显著。 | 组织课程调查团队，负责问卷结构、任务协作与报告终稿，形成完整的课程研究交付。（目标如为统计岗位且样本量重要，应如实提供） |
| “我去看了手术。” | 掌握外科技术及临床操作。 | 跟随带教医师观摩手术及诊疗流程，关注围术期管理和临床决策。（若具体术式已知才补） |
| “我得了某竞赛二等奖。” | 展现卓越综合实力、创新能力出众。 | 官方奖项名称 · 二等奖 · 年月／颁发方；若可证实作品及本人角色，附一句。 |
| “性格很好，学习能力强。” | 具有优秀团队精神和极强执行力。 | 追问一项真实事件，例如协调多人交付或自主完成课程工具；只有行为证据存在才写。 |
| “我们为此计划未来增加各种功能。” | 已实现全面能力、用户体验显著提升。 | 若有原型，写已完成的原型及设计；未实现功能不列为产出，必要时写规划/方案。 |

## 3. 成稿逐层审查清单（每项 PASS/FAIL/NA 与责任人、位置）
**读者层**：开头吸引注意但不浮夸；资格、方向、最强2–3项证据20–30秒可定位（内部扫读启发）；关联目标角色；选材与排序合理；新项目没有挤掉更强经历；行业必要词汇自然；读者不需先理解工具链才能理解价值。

**人物层**：主体清楚；能说出此人与一般同类候选者的实际差异；品质有行动证据；项目是为何、做了什么、形成什么；有适当专业语气；不同经历不重复泛泛能力；自介与未来目标功能不同；标题不故弄玄虚或宣传口号化。

**事实层**：身份、机构、职位、日期、学历、排名、奖名、数值与链接；区分参与/牵头/完成/观察、个人/团队/Agent；间接证据不变直接证据；没有虚构数字、工作、临床能力、引用或评价；必要状态清楚；无隐藏资格缺失；原资料冲突已处理；对外稿无内部审计痕迹和待核占位符；第三方隐私无泄露。

**语言层**：去空泛评价（卓越、全面、赋能、持续探索……若无具体信息则删）；去术语堆叠、突然缩写、技术目录语气、无意义数字；去“不是……而是……”式套路及重复对仗；不重复使用同一长句框架；中文专业名词、英文大小写及标点一致；可读短句优先，意图与贡献明确，词义不夸张；不要强制每条经历开头同一个动词。禁止为反AI而故意添加错字、俚语或假人类经历。

**结构/视觉层**：经历和章节语义明确，分页连续，正文与证据图关联；可点击链接无假地址；从PDF提取文本核对所有内容；没有占位、注释、修订痕迹；视觉与机器版真实事实一致；遵守09/12/13/14。

## 4. 独立隔离子代理审稿（有能力才实际调用）
主 Agent 完成 `COPY_DRAFT`、匿名化的 `CLAIM_LEDGER`、受众 `BRIEF` 和初步PDF 后启动可用的独立子代理；不分享私人对话、写作推理、被批准忽略的内部材料或原稿自评分。隐私遵循授权边界。三个角色可并行（不必为了形式必须三次）：
- Reviewer-A「读者盲审」：只收到面向读者的简历和目标要求，不能看到作者解释。20–30秒扫读后写：我记住谁/最强信号/最大困惑/最弱句/是否值得进一步了解及理由；不作保证录取。
- Reviewer-B「证据与行业审」：收到最小必要来源对照、岗位/学科约束以及初稿。逐条判定证据充分、歧义、虚构、角色被放大、隐私违规；列可最小修改的建议。不把无关内部缺点硬塞入简历。
- Reviewer-C「文案与视觉审」：收到可读稿和真实页图，检查上述清单，独立审查表达、栏目、读序、密度、图片/链接；可以标出位置和更好写法，不自行发布或覆盖。

子代理指令（可复用）：`你只担任独立审稿人。首先列事实和判断的边界；禁止因写作者自评而提高分数。按给定角色，逐条输出位置、观察证据、严重度P0/P1/P2、具体可执行修法、是否需要用户确认。无来源不补事实。不更改文件、不发布。` 输出记录于私有 `REVIEW_RECEIPTS`（实际 reviewer identity/agent id 若有、input version、timestamp、issues、evidence、suggestion、decision）。

P0：虚构/实质误导、隐私泄露、身份联系错、致命格式或未验收的发布；P1：严重相关性、文案、结构、视觉缺陷，需修复或明确用户选择；P2：可选细微审美改进。主 Agent 合并意见，发现冲突回证据与用户偏好，重写后由原 reviewer 或独立新审复核受影响部分。不得以评分替代红线。另保留 `REVIEW_STATUS = independent-completed / self-review-only / not-run`。当前环境没有独立Agent时，用同一模型两轮分角色检查并明确标注 `self-review-only`，不能伪称独立、隔离或已通过。不得无故把用户隐私送至外部服务。

## 5. 发布前通过条件
所有P0解决，P1有修复证据或用户确认的非实质性选择，必要事实无待核占位；用户拥有最终审核权。对外只交付成品，内部审查记录保留用户本地。短时间任务允许先出清楚标记的草稿，不伪称终稿。
