# 12｜照片、作品图片与荣誉证据的安置契约

适用阶段：0（披露决策）、1（素材归类）、4（结构审批）、6（排版）、7（审稿）。与09阅读密度契约同时生效。照片是可选身份信息，作品图是证明，二者都不能成为唯一的资历信息载体。


> **v1.3 优先级更新（必读）**：中国大陆面向真人阅读且用户已批准使用照片的正式简历，默认将照片放在身份区**右上独立式**，四款适配模板可选三栏式。原下表居中、左上、侧栏等位置成为**创意/编辑模式的兼容选项**，不能作为中文正式简历的默认方案。具体12款裁决、来源和渲染规则见 `references/19-chinese-formal-photo-design.md`、`templates/photo_policy.json`。

## 1. 先识别使用场景
- 按雇主/学校明确规范优先，其次是目标国家、行业与渠道习惯，最后才是个人偏好。不能通过国籍、外貌、年龄、性别或民族特征替用户判断照片价值。
- Harvard MCS 针对美国普通简历不推荐照片；德国联邦就业局指出德国部分行业照片仍常见而非强制。MIT ATS 指南建议避免图像/图标。[P1–P3]。因此 ATS 版本一律无头像、图标及作品图片；用户要个人照片时制作真人阅读版，不在机器版中强加。
- 不能由于用户上传一张自拍便默认许可把它放入外部简历。用户明确说“用这张头像”即可作为当前用途批准，不重复确认；只上传未说明用途时询问一次。不同收件人或公开分享另行判断。
- 若照片不合适，只讨论清晰度、裁切、光线、打印、比例、背景与授权，不评价长相。禁止未经同意用生成式编辑改变外貌；允许经用户授权裁切或调整曝光，保留原件。

## 2. 位置理论及反例
Gestalt 接近原则说明视觉距离会形成信息归组 [P4]；网格系统与排版层级（前版10）提供一致对齐。头像和姓名属于同一身份组，应置于第一页身份区，紧邻姓名，而非无缘由放在底部、角落、荣誉或研究区；它既不应遮挡核心内容，也不应成为第二个过重的入口。照片小而清楚优于大型装饰照。此原则从通用设计迁移而来，没有证据证明右上角必然更受招聘者欢迎。

| 预设 | 原创意/兼容位置 | 理由／适配边界 |
|---|---|---|
| ats-clean | 不显示 | 文本阅读顺序；另做真人版 |
| formal-split | 姓名身份子栏右缘 | 保持联系方式独立于身份；空间不足时身份区整行排列 |
| research-ledger | 身份区右侧 | 不干扰章节索引 |
| ivory-classic | 姓名正上方居中 | 延续对称、书信式轴线 |
| book-editorial | 左侧身份区姓名上方 | 避免抢占右侧自介；长自介转独立段 |
| studio-grid | 页首身份区右缘 | 不以头像填正文模块网格 |
| product-feature | 头部姓名区右缘 | 重点作品仍为正文焦点 |
| portfolio-rail | 左侧栏顶部、姓名上方 | 头像、姓名、身份、联系形成连续信息组 |
| experience-index | 页首右侧 | 经历时间轴独立 |
| bold-poster | 色带内姓名右方 | 平衡大字，与正文图像区区分 |
| pop-blocks | 彩色身份块顶部 | 不另造一个与身份竞争的色块 |
| two-track | 页首姓名右缘 | 两条经历轨道不放身份照片 |

默认尺寸 26×32 mm，海报允许30×36 mm，窄侧栏25×31 mm；这是本系统的版式起点，不是证件照标准或实证最佳值。防止切头，采用保留原比例的 crop 预览，用户核对脸部构图。无照片不生成边框、空洞和占位符；续页不重复头像。长姓名/窄栏若发生碰撞，将头像移至身份组上方或改用宽身份区，不缩小正文。手机自然单栏；纸面验收以 A4/Letter 为准。

## 3. 图片先做证据筛选，再选择载体
依据 Oxford creative CV/portfolio 指南 [P5]，作品集优先选最相关的强证据并解释本人贡献；不能以图片多证明经历丰富。每张图登记 `asset_id / source / rights / allowed_audience / mapped_claim / contribution / caption / alt / route / approval`。

| 图像类型 | 第一选择 | 不该做的事 |
|---|---|---|
| 项目截图、设计样张、研究图 | 紧邻相应项目，在文字说明之后；有必要时独立附录放大 | 单独拼贴图而无项目标题、角色或可读结果 |
| 奖状/证书 | 简历正文用真实奖项名称、颁发机构、时间；证据另存或按需附录 | 把每张证书缩得看不清，暴露证件编号/二维码 |
| 活动/会议照片 | 仅当它能说明与目标有关的贡献时，配角色/场景说明，通常附录 | 合照推断参与身份，披露未经同意的第三方 |
| 实验/临床、患者、公司内部及课程截图 | 先检查许可和敏感信息，能用脱敏文字/合规公开版本则优先 | 分享患者身份、公司数据或未授权的版权图 |
| 人像、无实质证明的装饰图 | 身份组或省略 | 填空、制造虚假构图或暗示资历 |

默认正文0–3张精选证据图，同一条经历最多2张（工程限额而非科学定律）；超出制作单独作品集/证据附录，或征求用户选择。主图与文字关联、保持比例、不强剪细节，caption说明图是什么而非凭空给它配荣誉。图表的关键结论必须在正文中也有可读文字。不用一张缩略图承担全部技术证明。多图版需评估真实打印尺寸，若模糊则移到附录。对视觉证明密集的申请，可主简历保持1–2页，另交独立作品集；按投递方实际要求执行。

## 4. 执行与程序契约
- `scripts/import_asset.py`：对经确认的本地 PNG/JPEG/WebP 重新编码，处理 EXIF 方向、去除图像元数据、限制尺寸；不意味着图片视觉内容已脱敏。通过 `--approved` 声明该用途的用户授权，严禁 Agent 自行假造授权。
- `photo: {src,alt,approved:true}`；`sections[].entries[].media: [{src,alt,caption,approved:true}]`。`src` 必须为本地导入的 raster data URI；禁止远程资源、未经清理的 SVG 和外部跟踪。不要把真实图像嵌进共享 Skill 或公共 gallery。图像体积大时需单独保存私有文件。
- `scripts/render_portfolio.py`：独立附录 `items[]` 每条为已批准素材 + heading + contribution + caption + alt + links；默认不自动把未审查原件拷进输出。附件所有作品按明确的选择顺序排列。
- `scripts/render_resume.py`：12种头像兼容规则；ATS 删除视觉元素但保留文案与链接；正式制作时渲染 Word/PDF，检查照片、caption、链接和分页。无照不留白框，头像不重复续页。
- W3C 的有意义图像使用等效文本、纯装饰图 alt 为空 [P6]。图标为装饰性附加信号，章节仍是可见文字。

## 5. 验收
照片正确的人/用途/授权；裁切无破坏；图片与对应事实、角色、caption 一致；不重复；未曝光隐私；视觉版与无图ATS版信息一致；不得让图片触发缩字号。凡自动分页预检异常需真实查看，不可据文字覆盖面积判定图文页空白。
