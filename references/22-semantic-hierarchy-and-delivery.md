# 22｜语义层级、页面容量与真实交付预检

## 视觉强调先编译语义，再实现样式
| 层级 | 内容 | 实现 |
|---|---|---|
| H0 | 姓名、身份、申请方向 | 姓名最大、身份紧邻；照片按19场景规范 |
| H1 | 主章节 | 统一样式、字号、位置、留白与色彩 |
| H2 | 经历/机构/项目标题、时间 | 独立行、适度字重、稳定对齐、日期次级 |
| H3 | 正文中的关键事实 | 短语强调（排名、身份、关键产出、获奖等级），不重复强化已在H2的角色 |

生成 emphasis map：语义类别、重要性、同类事实列表、目标样式、例外原因。只强化与目标读者直接有关的事实；同级角色/成绩/奖项同等处理。普通技术功能、泛标签、链接通常不是最高优先级。把正文的粗体单独抄出来做反向审查，确认读者真正应记住的是这些信息；去掉颜色再看层级是否成立。不能仅靠粗体修复结构、靠取消粗体解决拥挤。

## 容量预算（与09联合，保护线不变）
以实际纸张和输出字体测量，不按汉字数估计全部高度。优先删除重复/不相关内容，改写冗长句但保护正式题名和关键证据，调整条目归属、行宽、头像区域与非必要间距，最后才协商篇幅与例外。保留09正文≥10.5pt、行高≥1.5的默认工程保护线；不因为某次案例采用8.5pt或提出1.2倍就添加紧凑预设。强制机构模板与明确例外需记录原因、授权、实际纸面可读性、风险；未满足时交草稿或给取舍，不自动缩字/加页/加附录。底部余量不是可读性指标，单页不是成功的充分条件。

## 同源交付与范围
- 优先对最新原件做最小编辑；确需全局重排则使用统一内容源，锁定事实/链接/照片后生成可编辑稿及其实际导出的 PDF（如用户要求）。HTML 不等于 Word，不能用独立 HTML PDF 冒称 Word 导出。ATS/作品集/附录仅按渠道需求或用户授权提供。
- DOCX 精确编辑时保护 OOXML 的 w:t、runs、超链接关系、图片与样式；不要把 paragraph.text 整段赋值当成保持格式的操作。核验页眉/页脚、外部链接与可见文本，检查修订、评论、隐藏信息、属性及元数据。需要编辑或渲染时以实际环境的文档工具为准。
- 运行下面只读诊断；报告含私人正文和 URL，放私有审计目录，不外发：

```bash
python scripts/inspect_delivery.py --docx candidate.docx --pdf candidate.pdf --output private-delivery-audit.json
```

PDF 需要 PyMuPDF；DOCX 仅标准库。输出每页实际尺寸、字体字符数分布/主导字号、底部余量、粗体 flag 片段、URI、正文、越界提示；DOCX 提取含超链接的 XML 正文、链接目标和审阅痕迹指标。字体 flag 可能误判，正文提取顺序不等于阅读顺序，XML 检查不覆盖所有可能的 Word 隐藏内容及嵌入对象。报告永远是 diagnostics-only，不自动通过视觉、元数据、站点可达性或语义一致性。
- 实际渲染全部页，分别看整页与100%正文，检查纸张、字号/行距、照片、归属/断行、灰度、粗体、溢出、隐私。用逐条语义对照比较 DOCX 与 PDF，不要求机械逐字符相等；特别确认末条经历/奖项、正式名称和所有链接目标。记录工具、版本和结果；失败修复后再次渲染，不以预检成功代替审稿。
- 三种压力测试：20–30秒陌生读者扫读（启发式）、领域专家追问（回指证据）、反向视觉审查（只看强调词与灰度层级）。可用独立 Agent 则遵循16，不能调用则标 self-review-only，不伪造评审。
