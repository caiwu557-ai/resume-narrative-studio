# 13｜自适应版式、配色与个性化路由

适用阶段：0识别约束，3确定主张，4结构，6风格，7验收。继承09全局阅读契约，不增设高密度选项。布局、配色、字体、节奏分别独立；禁止偏好颜色导致重排已批准内容。

## A. 配色的标准答案
主理论为角色化设计令牌：USWDS 将中性色、主题色与强调色划分角色，以一致、可访问的组合维护系统 [P7]；W3C WCAG 1.4.3 为普通文字给出4.5:1对比下限 [P8]（网站标准，本 Skill 保守借用到所有有意义文字；不是打印认证）。传统色轮的同类色、互补色、分裂互补可作为色彩关系构思，不是必然和谐的定律；文化及个人联想不同，不能用“蓝色一定可靠、红色必然危险”替代判断。用户喜欢的颜色和投递用途决定情绪方向，角色、明度和对比度决定能否实际使用。

执行次序：
1. 捕捉“保留布局/字体/间距，只换色”等锁定要求，复制批准配置为新版本，内容保持不变。先让用户描述如“松弛的浅绿、不要偏蓝、不要橙”。从12套配色给出1套推荐和1套明显不同的备选，不问用户逐个 RGB 数值。
2. 如果已有喜欢的照片/作品/参考配色，用授权且可用的素材提取颜色或让用户给主色；不要用未经许可的机构标志或把照片放到外网取色。只需颜色时不需要把参考图嵌入简历。
3. 色彩角色：paper大面积浅底；ink主要正文；muted次级信息；accent标题、链接与关键线；panel浅底信息组；band身份色带；band_ink；highlight装饰强调块；highlight_ink；line分隔。每个角色都以对比度检查，正文不用低对比主色。一般先1主色+中性色，可按用户需求增1强调色；USWDS 60/30/10是网页非底色比例启发，不是简历固定比例。色彩不能唯一承载含义。
4. `scripts/make_palette.py --seed '#E5AA40' --secondary '#2F7269' --output custom-palette.json` 使用简单 sRGB 混色与对比校正产生角色令牌。适用于浅纸色；深底整页需另设计/验证，不暗自开启。若用户给黄色等低对比色，保留它作为强调或色块并生成深色可读文字，不要求用户改变审美；如原始色必须做浅底正文且不达标，解释冲突，提供最接近的深色替代。
5. `render_resume.py --custom-palette ...` / `export_pdf.py --custom-palette ...` 在原结构中渲染并核验。Gallery 可用既有预制颜色；自定义色工作流程通过脚本，不能声称任意混搭均已审美通过。ATS 锁定中性纸本/字体。
6. 渲染彩色、灰度/黑白、打印输出；检查深色块中文字、链接、附录和头像边缘。用户只需挑选效果。保存 `approved_design`，不暗中恢复默认。

## B. 如何选最适配的模板（可解释推荐，不是行业标签硬套）
输入先用自然语言分析，输出内部简短设计摘要：channel（ats/direct/unknown）、focus（clinical/research/academic/design/product/creative/general）、tone（formal/editorial/bold/young/playful）、volume（sparse/medium/long，以有效经历、行长、预计页数判断）、visual_evidence（none/weak/strong）、photo、layout_lock。用户明确偏好＞经批准的旧配置＞受众需要＞审美默认。强制模板/规定优先；不从敏感属性推测风格。

| 需要处理的设计条件 | 先选候选 | 反向淘汰条件 |
|---|---|---|
| ATS/格式严格 | ats-clean | 所有复杂图形布局；不夸大ATS兼容性 |
| 医疗/研究/学术 | research-ledger / formal-split / ivory-classic | 证据多且描述长时，不选窄侧栏或硬并排 |
| 项目核心突出/产品设计 | product-feature / studio-grid / portfolio-rail | 无强项目时不能人为指定featured；长文慎用网格 |
| 个人表达、创意 | pop-blocks / bold-poster / book-editorial | 面试场景正式程度不匹配；不凭职业猜审美 |
| 稀少但真实的素材 | ivory-classic / formal-split / book-editorial | 缺内容不凭空补栏目，不为了填满页面加照片或大块装饰 |
| 多任职、多日期/长学术CV | experience-index / formal-split / research-ledger | 不将所有信息强塞一页；正文维持10.5pt以上 |

`recommend_design.py --brief brief.json` 是候选路由器，按以上优先级输出候选与原因。Agent 要结合实际内容、用户反馈与渲染判断；不把这些规则当“最合适”的客观预测。先在统一内容下比较2–3个真正不同布局，用户不想参与时使用最佳稳妥候选并给撤销入口。用户已选择布局时不再问“要不要换布局”。仅当新的强制渠道/内容约束与锁定冲突才提出替代，并保留旧版。

## C. 内容变化适配矩阵（禁止固定模板占位）
根据目标读者、材料语义和真实内容选择栏目及跨度。无资料≠无能力，先挖能证明的课程/项目/服务/个人作品；没有就不虚构。信息有多少，页数就根据其相关性和可读性调整。

| 输入变化 | 编辑/布局动作 |
|---|---|
| 不需要自介/没有自介 | 删除整个块，保留姓名、身份、联系；不强制 tagline、目标或空白边栏 |
| 自介很少 | 1–2句作为身份区下方，不硬凑独立栏目 |
| 自介较多/个人陈述要求 | 提炼3个已被其他正文证明的主题；必要时独立全宽“个人简介”或单独陈述文件，保留用户原文于内部；不挤进半栏。简历默认非第一人称，个人陈述遵循用途 |
| 无作品集链接 | 删除链接区域；有真实成果用文字描述，不能造链接或要求必须创建 |
| 多个链接 | 页面顶部放最重要1–3个身份入口；每个项目下放对应链接。用短、人能读的标签，去重，版权/可访问性/权限验证。未核验链接列私有待核，不声称公开 |
| 新类型栏目 | 先判断与何种能力主张对应、是否有真实资料；与现有栏目合并或新增清晰标题，由用户确认重要结构改动 |
| 条目短而多 | 归组、日期索引、短栏目并排；不把关键叙述和辅助证据排成同权重 |
| 条目长、内容丰富 | 先筛写，采用全宽，允许多页/独立附录；若强制单页给精选与完整版选择，不缩字号 |
| 一页很空 | 检查是否确实缺证据；先针对性访谈。允许有自然留白，绝不可通过虚构、技能条或过量大装饰填满 |
| 多语言、长姓名、长链接 | 保留准确本名、官方英文名称，校对字体回退、断行、方向、链接和版式；切换行宽而不是缩字 |
| 纸张或输出要求改变 | 重新渲染分页及边界，不保留旧版视觉已通过的假设 |

渲染数据支持可选 photo/profile/contact/links、sections 任意数量、entries 一条或多条、文本或列表、多链接、inline media、featured 和 support；未提供块不输出内容。渲染不自行决定删减，非空原始事实仍需编辑批准；自介/附件位置由 Agent 语义规划。

## D. 用户偏好与变更锁
具体模式见 `templates/personalization_contract.json`。判断四种状态：用户明确（lock）、可推断（tentative）、用户委托（delegated）、未知（unknown）。偏好有范围：当前版本、当前申请方向、跨版本；不得把这次医学审美推广为所有行业或所有客户。允许推翻旧决定。先复述影响全局的1个决策，不重复已确认数据。

操作顺序：输入→意图摘要→继承约束→候选方案→确认必要冲突→变更→实际渲染→验证→保存；“只换配色”必须做结构和正文不变测试；“加一项项目”先检查结构优先级与分页；“照这个风格”分析结构/字体/色彩而不复制第三方作品。若用户表达不明确且调整可逆，直接给可编辑草稿；只有结果可能实质不同才问1个问题。
