# 07｜人类反馈是编辑监督信号，不是零碎修辞命令

## 标准反馈循环

`用户原话 → 可观察症状 → 根因假设 → 必须回滚的上游决策 → 修订方案 → 重新渲染/校验 → 用户确认`。

不得把“帮我别那么挤”仅解释为字体缩小；不得把“感觉不正式”仅解释为改配色。优先识别内容密度、信息架构、语域、页面重心和目标读者不匹配。

## 根因分类与补救

| 用户反馈 | 常见根因 | 处理方式 |
|---|---|---|
| “看不懂/太复杂” | 章节语义重复，正文信息层级不明，行文引用太多缩写 | 先合并/改名章节，删次要信息，再调整视觉 |
| “太挤，但底部很空” | 段间距不合理、密度集中、分页/内容块未按整页布局 | 先做整页重排，提升阅读节奏，再检查底部空白原因 |
| “第二页不像同一份简历” | 不一致的页眉、封面式大标题、突然改变语气 | 统一视觉系统与续页叙事，必要时移动章节 |
| “缺点太多/打击自己” | 将 QA 边界直接放入对外文本 | 内部保留检查，外部以准确、肯定、有证据的表达替代；不得掩盖实质资质问题 |
| “细节很多但无趣” | 把项目手册当申请人能力介绍 | 价值/行动/结果改写；仅在读者需要时恢复技术细节 |
| “数字没意义” | 盲目量化、缺乏目标关联 | 不强求数字；突出决策、组织、产物或有意义的影响 |
| “某个称呼不对” | 身份模型过期/没有征求本人判断 | 全局修正机构、角色、职位、时间与相关叙事 |
| “标题不概括/章节割裂” | 先起花哨标题，后塞入内容 | 重做分类、标题和章节边界，不只改文字 |
| “我有新作品/链接” | 素材库未持续更新 | 新增证据，重排优先级与相关章节，检查链接是否可访问 |

## 受控对抗审查（5个视角）

1. **真实收件人**：30秒能否辨识最强资格？哪些内容只是候选人自嗨？
2. **专业编辑**：每句的价值、主语、语气、衔接是否自然；哪里出现AI通用空话？
3. **行业评审**：有没有错误术语、错位的专业程度、研究/临床成果越界？
4. **事实审计员**：是否把计划当成成果；团队贡献、日期、荣誉、链接是否站得住？
5. **视觉与机器审查**：是否可扫读、文本复制顺序是否正确、页面是否出现拥挤、断裂及失衡？

## 红线与评分

不通过任一红线就不能标最终版：重大虚构；重大个人或第三方隐私泄漏；正文存在审稿占位符；明显的页面裁切/遮挡；联系信息错；错链/私链假装公开；两页合并逻辑错乱。其他项可内部用百分制：（目标与筛选30、经历贡献25、真实性20、连贯性10、视觉10、用户认可5）。**评分只用于内部迭代，不要强行把分数写进简历。**

## FEEDBACK_LOG 格式

| iteration | user_words | category | diagnosed_cause | fix | downstream_check | user_accepted |
|---|---|---|---|---|---|---|

`user_accepted` 只能由用户明确表达或其确认行为决定；不能把 AI 觉得漂亮写成用户认可。

## 交付前的检查

- 内容：全量要素是否遗漏、是否重复、是否值得放？
- 内容：所有时间、机构名、职务、奖项和可点击链接是否一致？
- PDF/Word：实际渲染所有页、检查长段落、悬挂标题、页末、页脚、中文字体、各页视觉密度。
- ATS：纯文本阅读顺序、标准标题、文件可解析；若无法检查，则如实说明未验证，不声称通过。
- 个人信息：附件/元数据/注释/隐藏修订/内审表是否被错误公开？
- 交接：可编辑版、稳定阅读版、必要时独立作品集与干净 ATS 版；文件名含用途和版本号。

## 建议验收回合

1. **内容审**：只看经历排序和每段文案，不被视觉吸引。
2. **视觉审**：只看页缩略图和排版节奏，必要时分页面评。
3. **最终读者审**：读一遍整稿，请用户说“最像我”与“最不像我”的段落；核实实际投递版本。

用户明确批准后再外发/安装/覆盖。允许保存新的私有文件用于用户审核，不自动同步第三方平台。
